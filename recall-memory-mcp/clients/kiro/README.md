# Recall memory — Kiro

Kiro is the one host of the three that reads an on-disk `mcpServers` JSON file,
so `recall-memory-mcp client-config kiro --write <path>` can configure it for
you — with a backup and a JSON read-back first.

Every key and path below comes from Kiro's current MCP configuration
documentation, recorded with its SHA-256 digest in
`artifacts/recall-mcp-cross-client/evidence/phase7-doc-sources.json`.

Primary source: <https://kiro.dev/docs/mcp/configuration>

## Where the file goes

- **Workspace:** `.kiro/settings/mcp.json` — applies to this workspace only.
- **User:** `~/.kiro/settings/mcp.json` — applies everywhere.

If both exist they are merged, with workspace winning. An agent config's own
`mcpServers` field outranks both.

## Two ways to install

Generated by the CLI, which backs up the existing file and reads the result
back before reporting success:

```bash
recall-memory-mcp client-config kiro
recall-memory-mcp client-config kiro --write ~/.kiro/settings/mcp.json
```

Or copy `mcp.example.json` and edit it. `--write` only replaces the
`recall-memory` entry; every other server in your file is preserved.

### CLI output versus the checked-in example

`client-config kiro` renders the server's active endpoint as one
`recall-memory` entry. Its default loopback form uses the local bearer-token
placeholder `${RECALL_MCP_TOKEN}` and is the variant that `--write` installs.
The checked-in `mcp.example.json` additionally demonstrates a remote OAuth
entry and a disabled loopback entry, so it is intentionally not byte-for-byte
equal to the CLI output. The local entry must still agree on the `/mcp` URL,
credential placeholder and read-only `autoApprove` list.

## The example file

`mcp.example.json` defines two entries:

- `recall-memory` — a remote HTTPS authority using Kiro's built-in OAuth flow.
  Kiro opens the browser and completes authorization for you.
- `recall-memory-local` — the loopback authority, `disabled: true` by default so
  the two do not fight. Enable this one if the authority runs on this machine
  and you are using a local bearer token instead of OAuth.

`url` must be HTTPS for a remote server; HTTP is only accepted for localhost.

For a local IDE workspace, grant the authority only the exact project scopes
that this server instance should expose. The default is deliberately
`global`-only, so a `project:<slug>` call otherwise fails closed:

```bash
RECALL_MCP_MEMORY_SCOPES=global,project:recall recall-memory-mcp serve
```

Use explicit comma-separated `global` / `project:<slug>` values. Empty entries,
wildcards, legacy scopes and malformed slugs are rejected at startup; do not
use a broad `project:*` grant.

## Secrets stay out of the file

No credential is ever written into `mcp.json`. Kiro expands `${VAR}` references,
so the example uses `${RECALL_MCP_OAUTH_CLIENT_ID}` and `${RECALL_MCP_TOKEN}`.

Kiro only expands environment variables that you have explicitly approved. If
the server silently fails to connect, check for the security warning listing
unapproved variables:

1. Open Kiro settings.
2. Search for **Mcp Approved Env Vars**.
3. Add `RECALL_MCP_TOKEN` and/or `RECALL_MCP_OAUTH_CLIENT_ID`.

For the Kiro CLI, export the variable in your shell before launching Kiro.

Commit `mcp.example.json` if you like. Never commit a file where those
placeholders have been replaced with real values.

## autoApprove is read-only, deliberately

`autoApprove` lists only `memory_get`, `memory_recent`, `memory_search` and
`memory_status`. `memory_add`, `memory_replace` and `memory_remove` are never
auto-approved: a write to shared memory that no human saw is exactly the
failure this project exists to prevent.

Kiro accepts `"*"` to auto-approve everything. Do not use it here.

## Steering

Copy `recall-memory-steering.example.md` into `.kiro/steering/` so the agent
knows when to search and when — rarely — to add. Without steering the agent
will either ignore the memory store or flood it.

## Prove it

Ask Kiro to `memory_add` one throwaway fact in a test scope, note the
`memory_id` and `revision`, then read the same id back from Claude, ChatGPT or
`recall-memory-mcp memory export`. Matching id, revision and content is the
only evidence that counts. A green connection indicator is not.
